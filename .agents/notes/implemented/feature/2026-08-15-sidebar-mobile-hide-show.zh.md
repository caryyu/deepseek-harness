# Agent Note：窄视口下侧边栏完全隐藏，由浮动显示/隐藏开关控制

Status: implemented

[English](2026-08-15-sidebar-mobile-hide-show.md) | 中文

## 问题

在手机宽度视口下，侧边栏从不离开屏幕。在自动折叠断点以下，它缩成 56px 控制窄条——在 375px 手机上仍然占用列宽，而且它的展开入口是窄条左上角鱼形/面板图标的悬停互换，这是桌面端悬停模式，在触屏上几乎不可用。用户希望默认让侧边栏完全让开，并有一个清晰的中高度控件把它唤回。

## 决策

在 `SIDEBAR_AUTO_COLLAPSE` 以下，侧边栏现在完全隐藏：关闭轨解析为零宽度而不是窄条。边界垂直中点有一个浮动箭头按钮作为抽屉开关——隐藏时它紧贴帧左缘、呈凸起状向右指（"显示"）；显示时它跨坐在列边框上向左指（"收起"）；它跟随与列相同的轨道过渡。箭头的 `aria-label` 与 `aria-expanded` 来自新的 `layout` 语言命名空间（与侧边栏自身开关相同的文案）。

机制：让步求解器新增 `closedSidebarWidth` 参数（默认 `SIDEBAR_COLLAPSED`，因此既有调用方与宽屏关闭窄条都不受影响），AppFrame 在窄屏隐藏态传入 0；布局 store 既有的 `narrowExpanded` 覆盖位就是显示/隐藏开关，store 无需改动。拖拽缩放是桌面端能力，断点以下不再渲染。隐藏的列保持子树挂载（slot 状态在抽屉切换间存活），但 `visibility: hidden` 只在轨道滑动结束后翻转——因此外壳的折叠淡出仍然对着移动中的列播放，窄条控件也会退出无障碍树与 Tab 顺序，而不是在零宽度下仍然可聚焦。

## 备选方案

- **保留窄条及其左上角开关**：否决——窄条在手机上仍占列宽，悬停互换的入口在触屏上不可用。
- **覆盖在中间列之上的抽屉**：否决——网格轨道动画已经存在；覆盖层需要新的图层与遮罩，而且中间列会在下方重排而不是吸收全部宽度。
- **用 store 偏好（0）隐藏**：否决——该偏好是宽屏关闭态；重新变宽时必须恢复挤压前的布局，这正是 `narrowExpanded` 覆盖位保留的语义。

## 后果

手机行默认得到全宽会话；点一下显示侧边栏，再点一下隐藏，箭头始终跟随移动中的边框。56px 窄条仍然是桌面端关闭态（关闭偏好）的呈现，宽屏行为不变。conversation-column-overflow e2e 扫描已重新录制：在窄屏停止点上，列宽增加了一个窄条的宽度，因此辉光溢出表及其空洞性守卫断言已同步更新。零宽度隐藏列在显示/隐藏之间保留 slot 状态（搜索文本、展开的树）。
